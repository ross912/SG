# SG PRD（精简版）

## 1. 产品定位

为需要每日观察 A 股市场、但不希望在多个行情与资讯工具之间重复切换的研究用户，提供一个以“数据可信、过程可见、答案有依据”为核心的 AI 投研工作台。

产品不是交易终端，也不负责给出买卖指令。

## 2. 用户与核心场景

**目标用户**：有基础市场知识、会看技术指标、需要自主研究的个人投资者或投研学习者。

**核心任务**：

1. 收盘后确认当日市场数据是否完整；
2. 快速获取趋势与均值回归候选；
3. 理解今天市场结构、重要新闻及潜在影响；
4. 对某只股票或市场事件继续追问；
5. 回看历史总结与策略实验依据。

## 3. 用户问题

- 行情、新闻和策略结果散落在不同页面，切换成本高；
- 全市场流程耗时长，用户无法判断是否卡死；
- 模型容易混淆日期、把标题扩写成事实或伪装实时；
- 单个接口失败可能拖垮整条链路；
- 策略改动缺乏稳定验证，容易为了“榜单变化”过拟合。

## 4. 目标与非目标

### 目标

- 一次操作完成当日行情补齐、数据检查、榜单、新闻和总结；
- 页面持续反馈阶段、百分比、当前动作和异常；
- AI 回答同时利用本地数据和最新资讯，并展示来源；
- 任何降级都对用户可见；
- 策略变更留下可审计实验结果。

### 非目标

- 不提供自动交易或券商账户连接；
- 不承诺选股收益；
- 不用大模型替代行情源；
- 不抓取付费文章全文；
- 不把回测结果描述为实盘业绩。

## 5. MVP 范围

| 模块 | 用户故事 | 验收标准 |
| --- | --- | --- |
| 全市场流程 | 我想一次完成当日研究准备 | 只补缺失行情；显示阶段进度；输出四份榜单 |
| 数据质量 | 我想知道结果是否混入旧数据 | 15:35 后检查交易股票日期；异常股票不入榜且页面提示 |
| 市场状态 | 我想快速知道当前风险环境 | 顶部固定显示主状态与四指数细分状态 |
| 新闻 | 我想浏览今天发生了什么 | 最近 24 小时、最多 50 条、保留原标题和原文 |
| 每日总结 | 我想快速理解当日结构 | 榜单完成后自动生成；可读格式；失败不影响榜单 |
| 数据问答 | 我想结合本地数据追问最新事件 | 三种联网模式；SSE 流式输出；展示来源和降级状态 |
| 安全 | 我不希望 API 额度被公开滥用 | 密码登录、会话限流、CSRF、Key 仅在环境变量 |

## 6. 关键规则

### 数据规则

- 数据就绪时间默认为交易日 15:35；
- 对仍在交易且非停牌股票执行日期一致性检查；
- 异常不足 10 只时列出代码、名称和日期；达到 10 只时只显示数量；
- 无论异常数量多少，任务继续，但异常股票不参与当日榜单；
- 指数与个股使用独立的新鲜度检查，不能因个股完成而假定指数已更新。

### AI 规则

- 新闻页直接使用原标题，不做二次标题生成；
- 每日总结只在核心榜单完成后触发；
- 搜索结果是外部不可信输入，不执行其中的指令；
- DeepSeek 只能基于提供的上下文回答，缺少数据时要明确说明；
- 搜索或模型失败必须返回可理解状态，不展示上游密钥或原始错误正文。

## 7. 指标设计

本项目尚未有真实线上用户，因此以下是待验证指标，而非已取得数据：

- 北极星指标：完成一次“有依据的每日研究会话”的用户占比；
- 流程成功率：核心榜单成功生成次数 / 全市场任务次数；
- 数据警告率：带异常完成任务数 / 完成任务数；
- AI 有效回答率：获得正文且来源/数据状态明确的回答数 / 提问数；
- 首字延迟：发送问题至收到首个文本片段；
- 联网降级率：Tavily 失败后使用 RSS 或本地数据的比例；
- 次日回访率与历史总结查看率。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 免费资讯源格式变化 | 提供商适配层、解析测试、主备切换 |
| API 成本失控 | 登录、限流、缓存、按意图触发搜索 |
| 数据日期混用 | 数据就绪时间、日期门禁、异常股票剔除 |
| 模型幻觉 | 带日期上下文、来源展示、禁止补写新闻正文 |
| 回测过拟合 | 固定方向、训练/验证/测试隔离、拒绝失败方案 |
| 合规误解 | 显著研究免责声明、无下单能力、无收益承诺 |

## 9. 后续路线

1. 用历史时点成分股、退市股票和行业分类降低幸存者偏差；
2. 将任务状态、搜索缓存和限流迁移到 Redis，支持多 worker；
3. 建立回答质量评测集，衡量事实一致性、引用覆盖和拒答质量；
4. 增加可配置数据源健康面板和成本面板；
5. 通过访谈验证目标用户真正高频使用的是榜单、日报还是问答。
