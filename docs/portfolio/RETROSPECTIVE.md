# 已知问题、失败实验与迭代复盘

## 一、没有上线的趋势因子重构

### 假设

将 12–2 动量、52 周高点、多周期波动调整动量、趋势质量和路径效率等候选因子加入生产组合，可以降低榜单长期重复并提升趋势策略稳定性。

### 实验设计

- 训练期：2022–2024；
- 验证期：2025；
- 测试期：2026 至实验日，仅作最终检查；
- 信号日收盘后选股、次日开盘成交；
- 计入佣金、印花税和滑点；
- 次日开盘封涨停视为不可买入；
- 因子方向预先固定，不因回测结果自动翻转。

### 结果

- 多个趋势候选在训练期和 2025 验证期的 Rank IC 为负；
- 标准化组合优于原始组合，但年化收益仍为负；
- 行业中性残差动量因历史行业覆盖不足被禁用；
- 没有方案同时通过绝对收益、超额 Sharpe 和最大回撤门槛。

### 决策

拒绝替换生产权重。保留研究代码与汇总结果，但不将“新因子更多”包装为产品进步。

### 学到什么

榜单重复可能是信号稳定，也可能是因子失效、数据偏差或持有周期设计问题。为了让榜单“看起来每天不同”而改权重，会把展示诉求错误地变成策略目标。

## 二、全市场数据日期不一致

### 现象

流程进度达到 100%，但榜单仍显示前一交易日；部分股票和指数已更新，部分仍旧。

### 根因

- 数据就绪时间早于上游稳定落库时间；
- 指数与个股新鲜度检查耦合；
- 局部缺失曾被当成整批失败，用户只能重跑全量。

### 迭代

- 数据就绪时间调整到 15:35；
- 增量补齐缺失区间，旧数据不重复抓取；
- 指数与个股分别检查日期；
- 交易中异常股票被排除；
- 任务不终止，少量异常列明明细，大量异常只报数量；
- 最终状态区分“完成”和“带警告完成”。

### 仍需改进

当前异常容忍策略优先保证研究可用性，但当缺失比例过高时，榜单代表性会下降。下一版应增加“覆盖率置信等级”，而不是只显示绝对数量。

## 三、AI 输出与等待体验

### 现象

- 每日总结和问答曾直接显示 Markdown 符号；
- 非流式问答让用户误以为页面失效；
- 搜索/DeepSeek 错误曾只出现在服务日志。

### 迭代

- 每日总结与问答共用受控 Markdown 渲染器；
- 问答改为 SSE 流式输出；
- 将检索、生成、降级状态展示给用户；
- 外部服务失败不影响已有本地数据和榜单。

### 仍需改进

- 缺少首字延迟、完整响应时间和中途断线率监控；
- Markdown 渲染器是受控子集，复杂表格展示有限；
- 目前回答质量依赖人工检查，尚无固定评测集。

## 四、联网搜索的能力边界

### 当前设计

Tavily 是主源，结果不足时补充 Google News 和 Bing News RSS；不抓文章全文，只使用标题、来源、时间、摘要和链接。

### 已知问题

- 免费 RSS 没有 SLA，格式可能变化；
- 搜索标题不等于完整事实；
- 进程内缓存不适用于多 worker；
- 搜索结果可能包含提示注入内容；
- 某些公告和中文财经内容的召回率仍不稳定。

### 下一步

- 引入正式公告和交易所数据源；
- 给来源增加可信度和时效评分；
- 将缓存、限流和任务状态迁移到 Redis；
- 建立问题—证据—答案三元组评测集。

## 五、作为 AI 产品经理项目的反思

做得较好的不是“接入 DeepSeek”，而是：

- 把模型能力放在数据管道之后；
- 把失败路径设计成正式产品状态；
- 明确核心产物和可降级增强能力；
- 对策略失败做可审计决策。

不足也很明确：

- 没有真实线上用户数据，很多指标仍是待验证假设；
- 目标用户画像来自自身使用场景，缺少系统访谈；
- 项目仍偏工程验证，下一阶段应验证日报、榜单和问答谁真正形成留存；
- 不应把约 5,000 只股票覆盖或测试通过数误写成业务增长指标。
